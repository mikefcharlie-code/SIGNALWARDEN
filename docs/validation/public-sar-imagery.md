## Limits

This implements genuine reduced-resolution provider browse imagery plus footprint maps, **not** calibrated full-resolution GRD/RTC/COG raster overlays. It does not verify ground truth, reconstruct publication times, guarantee current coverage/latency, or promise the absolute newest archive product when a bounded result set is full. Full ASF scientific-product downloads require Earthdata Login and separate tooling; public previews do not.

The fixed relay's delivery host/bucket allowlist can become stale and then fails closed. Browser cancellation prevents late rendering but an already authorized server download may finish its bounded original operation. ASF viewport refresh is opt-in, memory-only and bounded; there is no automatic pagination, silent alternate provider, or synthetic fallback. Umbra remains separately selected and manual because its verified public S3 workflow has no global spatial/date search. Local tests and screenshots do not establish deployment security, field validation, scientific calibration, or flight readiness.

## Opt-in viewport refresh follow-up

The updated production build was exercised in Chromium using fresh browser contexts and an intercepted ASF endpoint; **no real public provider was contacted**. There were zero provider requests on app load, opening the imagery controls, or selecting ASF while the saved permission was off. Turning the preference on while the globe was off-screen showed a paused state and still sent no request. Scrolling the globe into view produced two mocked GET searches because the initial orthographic/perspective view included the north pole and crossed the antimeridian; each request contained only `platform`, `processingLevel`, one `bbox`, `start`, `end`, `output`, and `maxresults`. No request body, cookie, authorization header, or referrer was sent. The mocked empty catalog displayed **No coverage returned**; turning the preference off stopped further requests. A second browser run forced WebGL initialization failure and verified the 2D globe fallback also made zero pre-opt-in requests and one bounded mocked request only after the globe was visible. A third run returned a real-shaped catalog fixture but mocked the local browse relay as HTTP 500; two catalog searches and one browse attempt produced a retained, provenance-labeled footprint, a visible failure message, and zero preview `<img>` elements—no substitute image appeared.

The viewport helper/controller/adapter/globe tests cover visible-frustum and orthographic bounds, date-line splitting, empty bounds and permission/source/visibility gating, debounce and minimum request interval, 15-minute cadence, aborts, leave/re-enter clearing, one browse preview maximum, no coverage, provider failure, attribution, historical age, and preview-not-georeferenced caveats. Final full-suite results for this follow-up: **610 Python tests passed** and **217 frontend tests passed**. TypeScript checking, the production build, and all 16 software-package notice checks passed. `pnpm audit` found **zero known frontend vulnerabilities** across 158 dependencies. The pre-existing production warning for the 525.80 kB minified globe chunk remains. The earlier separate Python tooling audit remains a non-clean baseline (83 advisory entries in Pillow, pip and pytest; see above); this follow-up adds no Python packages.

Bounding-box APIs cannot express a curved globe viewport exactly. Umbra has no verified global spatial/date search and remains manual; no additional imagery or tile provider was added. These checks were local only: no merge, deployment, aircraft command, autonomy action, or real upstream request occurred.
