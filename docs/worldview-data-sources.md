# WorldView data sources, terms and attribution

This is the source-control checklist for the current SignalWarden WorldView boundary. It cross-checks upstream `gods-eye-view` commit [`7be5937`](https://github.com/bilawalsidhu/gods-eye-view/tree/7be5937fc3e3b10cdfa8d3f833536167268768ad), especially its [`DATA_SOURCES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/7be5937fc3e3b10cdfa8d3f833536167268768ad/DATA_SOURCES.md), notices and model README, against the checked-out PR18 source.

**Important:** the upstream MIT license covers upstream code only. It does not grant rights to third-party data, imagery, models, trademarks, APIs or provider terms. Every adapter must preserve current provider attribution, obey terms/quotas/robots/geographic restrictions, and be disabled when a deployment cannot satisfy them. The matrix's **Key/config** column is deliberately explicit: “none” means the current adapter does not require a credential; “future” is a proposal, not a configured secret or working adapter.

## Operating rules

- No provider data or third-party visual asset is bundled by default in PR18 WorldView.
- Live reads are read-only, manually network-opted-in, bounded and source-labelled. Retain source URL, retrieval time, freshness/age, terms reference and transformation notes with rendered observations.
- Do not proxy around keys, quotas, billing, robots, attribution or geographic restrictions. Do not cache or redistribute data unless current provider terms allow it.
- Attribution must remain visible in the detail/source surface and any future export or recording mode where the provider requires it.
- Synthetic demo observations and user-authorized validated JSON packs are not live-provider data. Importing a pack does not verify provenance, licensing or freshness.

## Explicit exclusions and credential policy

- **TeleGeography cables and the Bhote Koshi flood pack are explicitly excluded**, not unresolved provider claims. They are upstream assets with noncommercial restrictions (CC BY-NC-SA and CC BY-NC 4.0 respectively). Do not bundle them in a commercial deployment without separate permission and a provenance review.
- **Datacenters and dams are also not bundled.** Their upstream snapshots are ODbL-derived and can only be added later with attribution/share-alike compliance, or supplied by an authorized imported pack with its own provenance.
- “Future `*_API_KEY`” entries above are planning labels only. PR18 has no configured WorldView API credentials and no adapter that reads those proposed variables. Do not add secrets to scene URLs, observation packs or client bundles.
- Provider status must distinguish **fresh**, **stale**, **failed**, **synthetic** and **unknown**. A marker, imported pack, event report or coarse camera pose is not proof of an event, identity, plate, location or threat.

## Current PR18 implementation

The current worktree contains original `WorldView.tsx`, `WorldGlobe.tsx`, `worldview-core.ts`, `worldview-globe-math.ts`, `worldview-open-feeds.ts` and satellite.js 6.0.2 orbit helpers. The live adapter set is limited to USGS earthquakes, NOAA/NWS `weather.gov`, and adsb.lol point observations. NASA EONET live reads are disabled pending per-source license review. The rest of this matrix is a terms/provenance boundary and future inventory; it does not authorize deployment, a Lattice sandbox, a provider key, a write path to PX4/ArduPilot or copying upstream code/assets.

## Public Sentinel-1 SAR imagery

An independent, session-opt-in [SAR imagery panel](worldview-sar-imagery.md) searches the public ASF catalog and loads genuine provider browse previews through a disabled-by-default local relay. Its map is footprint-only; full-resolution georeferenced SAR is not claimed. See [source access and licensing](worldview-sar-sources.md). It neither uploads observations nor changes other feed permissions.
