# Public SAR satellite imagery

SignalWarden AI can manually search the public ASF DAAC Sentinel-1 catalog and display genuine provider browse images alongside a footprint map. “Live” means the latest publicly available matching acquisitions returned by a bounded archive search—not streaming video, a continuously refreshed feed, or present-day ground truth.

## Start a search

In **World View**, open **Public SAR satellite imagery controls**. Opening the panel and choosing a source do not contact a provider. The new **Enable automatic refresh** preference is off by default; turning it on is the one-time, explicit permission saved on this browser. A previously saved permission does not fetch on application load: the imagery controls must be opened and a source selected, and the globe must be visible. Only ASF Sentinel-1 currently supports automatic viewport search. If Umbra is selected, the preference makes no Umbra requests because its verified public S3 workflow has no global spatial/date search; Umbra directory discovery remains manual.

While enabled and viewing the globe, ASF uses the visible camera-frustum bounds (WGS84 longitude/latitude), not aircraft, observations, uploaded files, annotations, scene selection, or surrounding application context. A date-line crossing is split into at most two provider bounding-box searches. The query uses a rolling 30-day UTC acquisition window, waits 750 ms for a stable view, allows at most one request per minute, then refreshes on a 15-minute cadence. Search and browse requests use `no-store`; only one latest returned browse image is requested per refresh. When the globe is no longer visible, the document is hidden, the source changes, the preference is turned off, or World View is left, in-flight reads are cancelled and in-memory automatic layers are cleared. The preference itself remains saved until the user turns it off.

Manual ASF search remains available in the source panel. Check **Enable public SAR reads for this session**, review the editable rectangle and UTC acquisition dates, then press **Search / refresh SAR**. Select an acquisition and explicitly press **Load selected SAR preview**. Enabling or selecting a scene alone does not download a browse image. Manual results also appear on the globe. Umbra continues to require its separate manual opt-in, directory/object actions, and explicit range-preview action. Manual overviews also appear on the globe but are not automatically queried by viewport. Provider failures and no coverage remain visible; no alternate source or fabricated image is substituted.

The visible globe layers retain the provider's footprint and acquisition/retrieval provenance. Browse images are shown as small cards pinned near the footprint, not warped over the globe: the image is genuine but not georeferenced. Source, product, acquisition age, retrieval time, coverage note, attribution, historical/stale state, and preview registration caveat appear on the globe. Data stays in browser memory and object URLs are revoked when cleared or replaced. The stored preference contains only an on/off boolean; no scene, bounds, image, or observation data is persisted or included in scene exports/share links.

## Configure the local browse relay

Catalog searches need no account or key. Image previews require the local Management API, explicitly started with `UCAS_PUBLIC_SAR_ENABLED=1`. Both Vite development and production-preview configurations forward only `/api/v1/public-imagery` to `http://localhost:8000`. A deployed installation must configure that same narrow, same-origin reverse-proxy route to its local API. If that route is absent, disabled, or misconfigured, the UI shows an error. No server-side read occurs merely by enabling the configuration; the UI opt-in, explicit Preview action, and dedicated request header are required too.

The relay accepts only public Sentinel-1 product identifiers, not URLs. It allows only the verified ASF hosts and exact delivery bucket path, omits provider credentials/referrers/cookies, bounds concurrency/time/bytes, and never exposes or logs short-lived provider-issued delivery strings. It does not introduce an account, secret, cloud processing service, or generic remote proxy.

## What the preview means

The browse image is the actual reduced-resolution product preview supplied by ASF, downloaded only for the selected scene through the fixed local relay. It is not generated, enhanced, classified, or synthesized by SignalWarden AI. Browse channel mapping and orientation may differ from the full scientific data. It is not necessarily north-up and is not a calibrated backscatter product.

The globe displays the provider's WGS84 footprint outline and a genuine browse-thumbnail card near the footprint centroid. The thumbnail is not registered to the globe surface and is never stretched over geographic polygons. Date-line-crossing footprints are kept; the card center uses circular longitude averaging. Umbra's locally decoded overview follows the same rule and remains a preview, not a registered raster layer. No external basemap or tile source is added.

Full-resolution products, radiometric calibration, orthorectification, RTC mosaics, measurements, interferometry, change detection, and live satellite tasking are not implemented. Full ASF product downloads require Earthdata Login and separate authorized tooling; no account, token, or secret is invented, bundled, stored, or requested by this panel. See the [source research and access comparison](worldview-sar-sources.md).

## Read the times separately

Every result retains its source/product identifier, acquisition start and end, platform, sensor, mode, polarization, orbit and direction, product type, and footprint. Processing time, publication time, resolution, and pixel spacing are shown only if actually supplied by the selected catalog record. Missing values are explicitly marked **Not provided by catalog**. Processing time and product metadata are not inferred from a filename or nominal sensor specifications. Retrieval time is never substituted for acquisition, processing, or publication time.

Catalog retrieval time and acquisition age are distinct. The manual panel labels catalog metadata stale after 15 minutes without refresh; automatic ASF refresh targets a 15-minute cadence while the globe is visible. Acquisitions older than 72 hours are separately labeled historical/stale on the globe; this is a display policy, not a provider freshness guarantee or mission requirement. Future/unparseable timestamps have unknown age. Recently retrieved catalog metadata does not make an old acquisition current.

The last submitted ASF query is linked so that bounds, date filters, product filters, and result limit remain inspectable. Editing fields does not relabel retained results; they remain tied to the last submitted query. Skipped invalid records are reported, not silently replaced. An empty response means no matching scenes were returned, not proof that no radar acquisition exists anywhere.

## Failures remain visible

HTTP, CORS, timeout, invalid metadata, unsupported image URLs, oversized responses, and invalid image content produce visible errors. A failed catalog refresh preserves previous data with a **RETAINED / REFRESH FAILED OR CANCELLED** label. A failed automatic browse keeps a matching previous preview explicitly marked as retained; when the latest catalog product differs, the older preview is cleared and only the new footprint remains as metadata. A failed image load never fabricates a replacement. A missing/disabled local relay is visible, not a reason to fall back. No alternate provider, synthetic image, cached demonstration, or optical imagery is silently substituted. An empty query reports **No coverage returned** for the requested area/date window; it does not claim that no acquisition exists.

Cancel, opt-out, source changes, hiding the document, leaving the visible globe, and leaving World View abort browser reads and invalidate late results. Hiding only the controls does not stop refresh while the globe remains in view. An already authorized local relay download may finish its bounded original request within the server deadline after the browser disconnects; cancellation does not recall a request already received by a provider. Object URLs are revoked when imagery is cleared or replaced. Only the on/off preference and selected source name are stored locally; imagery and viewport results are not. No service-worker cache, general-purpose provider proxy, or automatic retry loop is added. Requests use `no-store`; provider infrastructure may apply its own access logging and retention.

## Privacy and safety

Catalog reads are credential-free HTTPS GETs to a fixed ASF endpoint. Automatic requests transmit only the camera-visible WGS84 bounding box(es) and rolling 30-day UTC start/end dates; a date-line split has at most two boxes. Browse requests send a strictly validated product identifier to the same-origin local relay; the relay constructs a fixed ASF path and follows only validated ASF delivery redirects. Requests omit credentials and referrers, use `no-store`, reject arbitrary redirects, and have bounded durations and response sizes. Providers can still see normal network metadata, such as the requesting IP and the explicitly submitted search rectangle/dates or selected product path.

The viewport-query adapter receives only camera bounds and date limits; it has no props carrying aircraft state, observations, user annotations, operational context, credentials, or uploaded data. It does not upload user observations. Imagery is not used for AI evidence generation, autonomous decisions, mission planning, sensor tasking, or the civilian command gateway. The gateway introduced in PR #23 is unchanged.

SAR is radar backscatter, not an optical photograph or verified ground truth. Speckle, look/incidence angle, layover, radar shadow, polarization, moisture, terrain, processing choices, acquisition schedules, and dataset latency affect interpretation. Comparing passes requires appropriate scientific calibration and geometry. Do not treat a browse image as identification, a quantitative measurement, or a safe-navigation basis.

## Umbra Open Data: a separate source, not a fallback

Choose **Umbra — public SAR data** in the SAR imagery source selector. Switching sources clears/unmounts the previous browser session and does not read either provider. Enable Umbra explicitly, then press **Search / refresh Umbra directory**. Public S3 directory listing is not global spatial/time search: folder keys are lexicographic, not newest-first, and every folder/page/metadata/image read requires an operator action. Prefix changes and selections alone send nothing. Truncated pages have an explicit Next action; there is no recursive crawl.

The default `sar-data/tasks/` lists public locations. A verified example prefix is `sar-data/tasks/Bingham Copper Mine/9c39dad2-3539-4a7a-b755-47278c11fc96/2024-08-28-18-05-33_UMBRA-08/`. Explicitly search, load the listed `_METADATA.json`, then request the matching listed `_GEC.tif` overview. The original is 16001 × 16001 and 266,178,265 bytes; the verified stored overview is 500 × 500. The representative probe read 208,453 bytes in 12 requests, not the whole file. Other objects may require different amounts or fail safety limits; there is no full-file fallback.

The already-pinned GeoTIFF decoder reads HTTPS byte ranges under a total 8 MiB/40-request budget, 2 MiB single-range maximum, 20-second deadline, no redirects/cookies/referrer, and reduced single-band overview safety limits. Actual overview pixels are decoded locally and displayed with a documented log1p/2–98 percentile grayscale stretch. This deterministic display processing is not synthetic imagery or calibrated backscatter analysis. The map remains footprint-only: the overview is not stretched into a purported registered raster overlay. Source resolution, original dimensions, overview dimensions, pixel spacing, and display processing remain distinct.

Only actual listed keys become source/data links. Original scientific products are separate, explicitly clicked and potentially very large downloads; no AWS account/key is needed for the verified public objects. Umbra never uses or expands the ASF relay. Source metadata shows acquisition start/end, collect/task IDs, band/platform/mode/polarization, track/look direction, orbit values when supplied, resolution, footprint and attribution. Unknown processing/publication time and pixel spacing remain unknown. S3 LastModified and STAC metadata-created/updated fields are not relabeled as publication/acquisition time.

The [source verification](worldview-sar-sources.md) and distributed notices explain CC BY 4.0 attribution, the historical/incomplete static STAC index, and the generic website-terms mismatch at the registry's Umbra open-license link. Matching license text at that provider URL was not verified; the CC BY basis is the official registry plus a checked STAC license declaration. Directory/acquisition freshness and failure indicators remain visible, with the same SAR interpretation limits and no observation uploads or autonomous/hardware action.
